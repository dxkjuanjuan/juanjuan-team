# Juanjuan Team 模型分层（v2.0）

> v2.0 落地模型分层。卷卷说 Token 不考虑，但模型分层不是为省 Token——是为了**让 reviewer/sub 用合适模型，避免 Haiku 漏 OWASP 级问题**。

---

## 一、模型分层原则

1. **Convener / Architect**: 用最强模型（Opus）——综合判断 + 架构设计需要深度推理
2. **Coder / Frontend / Docs-Researcher**: 用 Sonnet——实施 + 写文档够用
3. **Reviewer**: 用 Sonnet（不用 Haiku）——挑错需要深度，MVP 阶段不能让"模型太弱"和"机制不行"两个变量混淆
4. **Sub-agent**: 用 Haiku——只做细分任务（如 OWASP checklist），不需要创造
5. **Leader**: 用 Sonnet——裁决需要深度，但不需要 Opus

---

## 二、agent 文件的 model 字段

每个 `~/.claude/agents/juanjuan-*.md` 的 YAML frontmatter 已设 `model:` 字段：

| Agent | model | 理由 |
|-------|-------|------|
| juanjuan-convener | opus | 综合决策需要深度推理 |
| juanjuan-leader | opus | 裁决需要深度（v2.0 用 opus 而非 sonnet，避免裁决失误） |
| juanjuan-architect | opus | 架构设计需要深度 |
| juanjuan-coder | sonnet | 实施不需要 opus 那么深 |
| juanjuan-frontend | sonnet | 实施不需要 opus |
| juanjuan-reviewer | sonnet | 挑错需要深度，不用 haiku |
| juanjuan-docs-researcher | sonnet | 写文档够用 |

## 四、spawn 时怎么指定模型

### 4.1 Agent Teams teammate

```bash
Agent({
  subagent_type: "juanjuan-architect",
  name: "architect",
  model: "opus",  # 显式指定
  prompt: "...",
  run_in_background: true
})
```

### 4.2 claude -p 真进程

```bash
claude -p \
  --model opus \  # 显式指定
  --append-system-prompt "..." \
  --dangerously-skip-permissions \
  ...
```

### 4.3 Sub Agent

```bash
Agent({
  subagent_type: "typescript-reviewer",
  model: "haiku",  # 显式指定
  prompt: "..."
})
```

## 五、模型分层的好处

1. **挑错质量**: reviewer 用 Sonnet 能挑出 OWASP 级问题，Haiku 可能漏
2. **成本可控**: sub 用 Haiku 减少 token 消耗（卷卷说不考虑 Token，但 sub 用 Haiku 是质量选择不是成本选择）
3. **职责匹配**: 主角色用 Opus 做深度决策，sub 用 Haiku 做 checklist——各司其职

---

## 六、模型降级机制

如果 Opus 限流不可用：
1. 主角色自动降级到 Sonnet（仍能跑）
2. Sonnet 限流降级到 Haiku（仅 Lite 任务能跑）
3. Haiku 限流：暂停任务，等恢复

降级时 convener 提示卷卷"Opus 限流，已降级到 Sonnet"。

---

## 七、YAGNI

- 不做模型自动选择（按任务复杂度选模型）——v2.0 用固定分层
- 不做模型 A/B 测试——v2.1 再加
- 不做跨提供商（OpenAI/Anthropic）模型切换——v2.0 只用 Claude
