# Juanjuan Team 跨平台抽象层（v2.0）

> v2.0 设计薄接口，让 juanjuan-team 未来兼容 Codex / Gemini CLI / 其他平台。
> v2.0 只实现 Claude Code 后端，v2.1+ 加其他平台。

---

## 一、设计原则

1. **薄接口**：只定义 4 个核心方法，不过度抽象
2. **v2.0 只实现 Claude Code**：不提前实现其他平台
3. **role-*.md 不硬编码平台术语**：用通用词"通信通道""任务派发"
4. **后端可插拔**：v2.1+ 加 Codex/Gemini 只新增后端实现，不改 role-*.md

---

## 二、4 个核心方法

```typescript
interface AgentBackend {
  // 1. spawn 一个 agent
  spawnAgent(role: string, prompt: string, options: SpawnOptions): AgentHandle;
  
  // 2. 给 agent 发消息
  sendMessage(to: AgentHandle, message: string): void;
  
  // 3. 等待 agent 完成（或超时）
  waitForCompletion(handle: AgentHandle, timeoutMs: number): AgentResult;
  
  // 4. 注册 sub-agent 类型
  registerSubAgent(name: string, definition: SubAgentDef): void;
}
```

## 三、v2.0 实现的 3 个后端

### 3.1 Claude Code Agent Teams 后端（Lite/Medium）

```bash
# spawn
Agent({
  subagent_type: "juanjuan-architect",
  name: "architect",
  prompt: "...",
  run_in_background: true
})

# send
SendMessage({to: "architect", message: "..."})

# wait
# (teammate 完成后自动通过 teammate-message 事件通知)
```

### 3.2 Claude Code `claude -p` 后端（Complex）

```bash
# spawn
bash scripts/global-spawn.sh <team> <role> <prompt-file> <project-dir>

# send (文件消息)
bash scripts/mailbox.sh send <team> <from> <to> <type> <payload-file>

# wait
wait <pid>
```

### 3.3 Claude Code Sub Agent 后端（v2.0 新增，sub-agent team）

```bash
# spawn (主角色在自己进程内调)
Agent({
  subagent_type: "typescript-reviewer",
  description: "...",
  prompt: "..."
})

# 不需要 send/wait——sub 是一次性返回
```

## 五、role-*.md 的平台无关性

role-*.md 里不写 `Agent({...})` 或 `claude -p` 这种平台术语，改用通用指令：

```markdown
## Phase 3 工作流程

convener 现在应该 spawn 一个 architect。
spawn 方式由当前后端决定（Agent Teams / claude -p / Codex / Gemini）。
prompt 参数填入：任务描述 + requirements.md 内容。
```

这样 v2.1 加新后端时，role-*.md 不用改。

---

## 六、后端选择逻辑

```bash
# scripts/select-backend.sh
if [ "$TASK_LEVEL" = "Complex" ]; then
    BACKEND="claude -p"
elif [ "$TASK_LEVEL" = "Lite" ] || [ "$TASK_LEVEL" = "Medium" ]; then
    BACKEND="agent-teams"
fi

# sub-agent 永远用 Sub Agent 后端（不分任务级别）
```

## 七、YAGNI（v2.0 不做）

- 不实现 Codex/Gemini/HAPI 后端（v2.1+）
- 不做后端自动 fallback（Complex 失败不降级到 Agent Teams，让卷卷决定）
- 不做跨后端通信（Claude Code 的 teammate 不能给 Codex 进程发消息）
