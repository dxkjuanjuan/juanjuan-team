# Juanjuan Team 防断联机制（v2.2）

> Claude Code 退出 / claude -p 真进程死了 / 电脑断电 -- 怎么续上？

---

## 一、3 种断联场景

| 场景 | 影响 | 恢复方式 |
|------|------|---------|
| Claude Code 进程退出 | 主会话没了，但 spawn 的 claude -p 真进程可能还在跑 | 重启 Claude Code，调 resume.sh |
| claude -p 真进程死了 | architect/reviewer 等死了，产出可能写一半 | 调 resume.sh，自动清理脏数据 |
| 电脑断电 | 所有进程都没了，文件可能写一半 | 重启电脑，调 resume.sh |

## 二、状态追踪机制

### 2.1 phase-state.json

每个项目目录下有 `.convener/phase-state.json`：

```json
{
  "task_id": "<项目目录名>",
  "current_phase": "Phase 4",
  "current_phase_status": "in_progress",
  "in_progress_agent": "reviewer",
  "in_progress_started_at": "2026-08-05T03:30:00Z",
  "completed_phases": ["Phase 0", "Phase 1", "Phase 2", "Phase 3"],
  "last_updated": "2026-08-05T03:30:00Z"
}
```

每个 Phase 开始/结束 convener 都会更新这个文件。

### 2.2 audit events.jsonl

每次 spawn Agent 都追加 2 条事件到 `.audit/events.jsonl`：

```json
{"event":"agent_spawn","agent":"reviewer","timestamp":"...","spawn_method":"claude -p"}
{"event":"agent_complete","agent":"reviewer","timestamp":"...","duration_seconds":180}
```

断联时如果 `agent_spawn` 有但 `agent_complete` 没有，说明这个 Agent 死了。

## 三、恢复流程

### 3.1 一键恢复

```bash
bash ~/.claude/skills/juanjuan-team/scripts/resume.sh <项目目录>
```

resume.sh 自动做：
1. 读 phase-state.json
2. 发现 in_progress agent -> 检查产出完整性
3. 不完整 -> 调 cleanup-stale.sh 清理脏数据
4. 完整 -> 自动标记完成
5. 输出下一步建议（继续哪一 Phase / 重新 spawn 哪个 Agent）

### 3.2 手动恢复

如果想手动检查：

```bash
# 1. 看当前状态
cat <项目>/.convener/phase-state.json | jq .

# 2. 看哪些 Agent 死了（有 spawn 没 complete）
jq -r 'select(.event == "agent_spawn") | .agent' <项目>/.audit/events.jsonl | sort | uniq -c
jq -r 'select(.event == "agent_complete") | .agent' <项目>/.audit/events.jsonl | sort | uniq -c

# 3. 清理脏数据
bash ~/.claude/skills/juanjuan-team/scripts/cleanup-stale.sh <项目>

# 4. 重新 spawn 死掉的 Agent
bash ~/.claude/skills/juanjuan-team/scripts/global-spawn.sh <team> <role> <prompt> <项目>
```

## 四、auto-spawn.sh 自动包装（推荐）

v2.2 新增 `scripts/auto-spawn.sh`，自动做：
1. spawn 前更新 phase-state.json（标 in_progress）
2. 写 agent_spawn audit event
3. 调 global-spawn.sh 启动真进程
4. 等进程完成
5. 写 agent_complete audit event
6. 更新 phase-state.json（标 completed）

**用法**：

```bash
bash scripts/auto-spawn.sh <项目目录> <team-name> <role> <prompt-file>
```

**好处**：不用手动写 audit event，断电时 phase-state.json 始终最新。

## 五、产出完整性检查

cleanup-stale.sh 检查每个 Agent 的产出是否完整：

| Agent | 完整性检查 |
|-------|----------|
| architect | design.md 有 `# Design` 开头 + `## 10. 风险点` 结尾 + 行数 ≥ 50 |
| reviewer | review.json 是合法 JSON + 有 verdict 字段 |
| leader | verdict.json 是合法 JSON + 有 leader_decision 字段 |
| docs-researcher | spec.md 行数 ≥ 10 |
| coder | stub.ts 行数 ≥ 10 |
| frontend | stub.tsx 行数 ≥ 10 |

不完整的产出会备份到 `.audit/stale-<timestamp>/`，然后删原文件，让 Agent 重新 spawn。

## 六、断联恢复示例

### 场景 1: Phase 4 reviewer 跑到一半 Claude Code 退出

```bash
# 重启 Claude Code 后
bash scripts/resume.sh ~/项目/url-shortener-2026-08-05-0327-49c2

# 输出:
# === Juanjuan Team 断联恢复 ===
# 当前 Phase: Phase 4
# Phase 状态: in_progress
# in_progress Agent: reviewer
# === 检查 in_progress Agent (reviewer) 产出完整性 ===
# ✗ review.json 不是合法 JSON -> 备份+清理
# ⚠️ 上次 reviewer 跑了一半就断了，脏数据已清理
# 建议: 重新 spawn reviewer 跑 Phase 4
```

### 场景 2: Phase 8 reviewer 跑完了但 phase-state 没更新

```bash
bash scripts/resume.sh ~/项目/url-shortener-2026-08-05-0327-49c2

# 输出:
# ✓ reviewer 产出完整，可继续下一 Phase
# 已自动标记为完成
```

### 场景 3: 项目正常完成

```bash
bash scripts/resume.sh ~/项目/url-shortener-2026-08-05-0327-49c2

# 输出:
# ✓ 上次正常完成，无需恢复
# 建议: 继续 Phase 12（或新任务）
```

## 七、最佳实践

1. **用 auto-spawn.sh 代替 global-spawn.sh**：自动写 audit + 更新 phase-state
2. **每次断联后先跑 resume.sh**：不要手动判断状态
3. **重要任务配 git commit**：每个 Phase 完成后 commit，断电也能从 git 恢复
4. **备份在 Phase 9 自动做**：tar.gz + git bundle，断电后文件还在

---

## 八、不做（YAGNI）

- 不做跨机器恢复（v2.3+ 加 HAPI Remote 后端再说）
- 不做自动重试（resume.sh 只报告状态，不自动重 spawn）
- 不做实时心跳（v2.3+ 加 teammate 心跳检测）
