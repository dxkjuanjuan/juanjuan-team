# Juanjuan Team 项目命名聚合（v2.2）

> 同一项目不同时间跑，怎么聚合？卷卷说"接着跑 todo-list"怎么找到原项目？

---

## 一、命名规则

### 1.1 v1.8 之前（旧）

```
~/项目/YYYY-MM-DD-HHmm-<任务简述>-<rand4>/
例: ~/项目/2026-08-05-0327-url-shortener-49c2/
```

**问题**: 同一项目下次跑会建新目录，跟上次的不连。

### 1.2 v2.2（新）

```
~/项目/<project-id>-<timestamp>-<rand4>/
例: ~/项目/url-shortener-2026-08-05-0327-49c2/
    ~/项目/url-shortener-2026-08-06-1430-a3f2/   ← 同 project-id 不同时间
```

**project-id** 是卷卷第一次说任务时 convener 提取的：
- "做 URL 短链接系统" -> project-id = `url-shortener`
- "做 TODO list" -> project-id = `todo-list`
- "做百万用户登录系统" -> project-id = `login-system`

## 二、registry.json 注册表

`~/.juanjuan/registry.json` 持久化所有项目：

```json
{
  "url-shortener": {
    "first_created": "2026-08-05T03:27:00Z",
    "project_dirs": [
      "~/项目/url-shortener-2026-08-05-0327-49c2/",
      "~/项目/url-shortener-2026-08-06-1430-a3f2/"
    ],
    "latest_dir": "~/项目/url-shortener-2026-08-06-1430-a3f2/",
    "status": "active | completed | paused"
  },
  "todo-list": {
    "first_created": "2026-08-04T00:52:00Z",
    "project_dirs": ["~/项目/todo-list-2026-08-04-0052-5bf9/"],
    "latest_dir": "~/项目/todo-list-2026-08-04-0052-5bf9/",
    "status": "completed"
  }
}
```

## 三、命令

### 3.1 注册新项目

```bash
bash scripts/registry.sh register <project-id> <project-dir>
```

### 3.2 列所有项目

```bash
bash scripts/registry.sh list
```

输出:
```
url-shortener [active]: 2 dirs, latest=~/项目/url-shortener-2026-08-06-1430-a3f2/
todo-list [completed]: 1 dirs, latest=~/项目/todo-list-2026-08-04-0052-5bf9/
```

### 3.3 查最新目录

```bash
bash scripts/registry.sh latest <project-id>
```

### 3.4 改状态

```bash
bash scripts/registry.sh status <project-id> <new-status>
# new-status: active | completed | paused
```

### 3.5 接着跑（v2.2 新增）

```bash
bash scripts/continue.sh <project-id>
```

自动做：
1. 查 registry.json 找最新目录
2. 调 resume.sh 检查状态
3. 输出下一步建议

**示例**:
```bash
$ bash scripts/continue.sh url-shortener
=== 接着跑: url-shortener ===
最新目录: ~/项目/url-shortener-2026-08-05-0327-49c2

=== Juanjuan Team 断联恢复 ===
当前 Phase: Phase 11
Phase 状态: completed
✓ 上次正常完成，无需恢复
建议: 继续 Phase 12（或新任务）
```

## 四、跨项目记忆聚合（v2.3+ 待做）

卷卷说"跨项目记忆聚合不是存记忆+读取吗？"--对，**就是存+读**。

### 4.1 当前机制（v2.2 已有）

- **Phase 10 存**: docs-researcher 把经验存到 `~/.jaaos/memory.json`
- **Phase 0.5 读**: docs-researcher 查 memory 找相关历史经验

这就是"存+读"，已经做了。

### 4.2 复杂版（v2.3+ 不做，留研究）

把多个项目记忆连成知识图谱（Neo4j）：
- 节点: 项目 / 技术 / 踩坑 / 角色
- 边: 项目A -> 踩坑 -> SSRF
- 查询: "SSRF 在不同项目里出现过几次？"

**这个是研究性工作，v2.3+ 再做，卷卷说"到时候再说"**。

## 五、最佳实践

1. **project-id 用 kebab-case**: `url-shortener` / `todo-list` / `login-system`
2. **同 project-id 不同时间**: 加时间戳 + rand4 区分
3. **断联后先跑 continue.sh**: 自动找最新目录 + 检查状态
4. **完成的项目改 status**: `completed` 后下次不会误选

---

## 六、不做（YAGNI）

- 不做 project-id 自动提取（convener 手动判断）
- 不做跨 project-id 聚合（每个 project-id 独立）
- 不做 project-id 重命名（建好后不能改）
