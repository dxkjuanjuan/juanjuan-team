## 二、每个 Phase 的执行细节

### Phase 0: 头脑风暴

- **执行者**: convener
- **动作**: 跟卷卷对话澄清需求，整理 `.shared/requirements.md`
- **spawn 方式**: convener 是主会话本身，不 spawn
- **产出**: `.shared/requirements.md`

### Phase 0.5: 资料查询

- **执行者**: docs-researcher
- **动作**: 查 ruflo memory + kimi-webbridge，整理历史经验
- **spawn 方式**:
  - Lite/Medium: Agent Teams teammate
  - Complex: `claude -p` 真进程
- **产出**: `.docs-researcher/findings.md`

### Phase 1: 模式选择

- **执行者**: convener
- **动作**: 用 AskUserQuestion 让卷卷选 Safe/Manual/Auto/YOLO
- **产出**: `.convener/mode-choice.json`

### Phase 2: 建项目目录

- **执行者**: convener
- **动作**: 建项目目录 + 注册 registry.json + 初始化 phase-state.json
- **命名**: `~/项目/<project-id>-<timestamp>-<rand4>/`
- **产出**: 项目目录结构

### Phase 3: 方案生成

- **执行者**: architect
- **动作**: 出 2-3 方案 A/B/C，写 design.md + reasoning.md
- **spawn 方式**:
  - Lite/Medium: Agent Teams teammate
  - Complex: `claude -p` 真进程
- **产出**: `.architect/public/design.md` + `.architect/private/reasoning.md`

### Phase 4: 方案审核

- **执行者**: reviewer（盲审）+ architect（自审）+ docs-researcher（查历史坑）
- **动作**: 三方独立审方案，convener 综合
- **spawn 方式**:
  - Lite/Medium: Agent Teams teammate
  - Complex: `claude -p` 真进程
- **产出**: `.reviewer/reviews/design-review.json` + `.convener/decision.md`

### Phase 5: 设计文档

- **执行者**: docs-researcher
- **动作**: 基于 architect 定稿写 spec
- **产出**: `.docs-researcher/spec.md`

### Phase 6: 文档审核

- **执行者**: reviewer（单向审，不互审）
- **产出**: `.reviewer/reviews/spec-review.json`

### Phase 7: 实施

- **执行者**: frontend + coder（并行）
- **动作**: 按接口契约并行写代码
- **spawn 方式**:
  - Lite: 仅 coder（无 frontend）
  - Medium: coder + frontend（Agent Teams）
  - Complex: 全 7 角色（`claude -p` 真进程）
- **产出**: 源代码 + 测试

### Phase 8: 代码审查

- **执行者**: reviewer + sub-agent team
- **动作**: 审代码 + OWASP + 测试覆盖率
- **spawn 方式**:
  - Lite: 仅 reviewer（Agent Teams）
  - Medium: reviewer + 2 sub
  - Complex: reviewer + 4 sub（typescript-reviewer / security-reviewer / silent-failure-hunter / type-design-analyzer）
- **产出**: `.reviewer/reviews/code-review.json`

### Phase 9: 智能备份

- **执行者**: convener（触发）+ 备份脚本
- **动作**: reviewer verdict=pass 事件触发，tar.gz + git bundle
- **产出**: `.backups/YYYY-MM-DD-HHmm-<task>.tar.gz` + `.bundle`

### Phase 10: 存记忆

- **执行者**: docs-researcher
- **动作**: 存经验到 ruflo memory（key=project-id，namespace=project）
- **产出**: ruflo memory entry

### Phase 11: 汇报归档

- **执行者**: convener
- **动作**: 给卷卷最终汇报 + 归档
- **产出**: `.convener/final-report.md`

## 三、任务级别与 Phase 关系

| 任务级别 | 跑哪些 Phase | 用什么 spawn |
|---------|------------|------------|
| Lite | 0, 1, 3, 7, 8, 11 | Agent Teams teammate |
| Medium | 0, 0.5, 1, 2, 3, 4, 7, 8, 11 | Agent Teams teammate |
| Complex | 全部 11 + 0.5 | `claude -p` 真进程 |

---

## 四、Phase 间通信

### Lite/Medium（Agent Teams）

- convener 用 `SendMessage` 跨 teammate 通信
- teammate 之间也用 SendMessage

### Complex（`claude -p` 真进程）

- 进程间不能 SendMessage（不同进程）
- 用**文件消息协议**：
  - `<team_dir>/mailbox/<from>_<to>_<phase>_<ts>.json`
  - 每个 agent 轮询自己的收件箱

---

## 五、Phase 状态管理

每个 Phase 完成后更新 `.convener/phase-state.json`：

```json
{
  "current_phase": "Phase 4",
  "current_phase_status": "completed",
  "completed_phases": ["Phase 0", "Phase 0.5", "Phase 1", "Phase 2", "Phase 3"],
  "last_updated": "<ISO 8601>"
}
```

断电恢复时，convener 读 phase-state.json 接着跑。

---

## 六、YAGNI（v2.0 不做）

- 不做 Phase 内的子流程（保持 Phase 原子性）
- 不做 Phase 跳过（按顺序跑，除非卷卷显式覆盖）
- 不做 Phase 并行（每个 Phase 等上一个完成）
